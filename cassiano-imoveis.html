01 • O Problema

Um catálogo que só mudava quando o desenvolvedor mexia

Uma imobiliária vive de anúncios atualizados. Quando cada imóvel novo, foto trocada ou descrição corrigida precisa passar por um desenvolvedor, o site fica para trás e vira um gargalo: o imóvel já está disponível, mas ainda não aparece.

Na temporada, o desafio era outro: enxergar a ocupação de todas as casas no mesmo período e continuar entregando a planilha no modelo com que o cliente já trabalhava.

E havia uma condição: não abrir mão do que já funcionava. O site precisava continuar rápido, fácil de encontrar no Google e, acima de tudo, sempre no ar.

02 • A Solução & Como Funciona

Site estático, painel próprio e publicação com um botão

A solução separa o que o visitante vê do que o dono administra. O site continua estático e leve; o conteúdo passa a morar num banco de dados que o dono controla pelo painel, e um botão transforma esse conteúdo em site novo.

01 / STATIC SITE

Site em Astro no Cloudflare Pages

As páginas são geradas de forma estática em Astro e servidas pelo Cloudflare Pages, com domínio próprio. O visitante recebe HTML pronto e leve, sem um servidor montando a página a cada acesso.

02 / ADMIN PANEL

Painel administrativo próprio

Painel em /admin feito em HTML, CSS e JavaScript puros, com Content Security Policy estrita. A API é uma Cloudflare Pages Function sobre Supabase (Postgres + Auth, região São Paulo), conectada via Hyperdrive. Perfis admin e assistente têm permissões diferentes: o assistente não exporta nem apaga.

03 / SAFE PUBLISHING

Publicação segura

O botão “Publicar no site” dispara um novo build, que gera o site a partir do banco. Se a leitura do banco falhar, o build falha de propósito e o site anterior continua no ar. Publicar nunca quebra o site.

Como funciona a publicação
1. Cadastro no painel O dono cria ou edita o imóvel, envia as fotos e escolhe os ícones das características.
2. Banco de dados Os dados ficam no Supabase (Postgres) e as fotos no Supabase Storage.
3. Publicar no site Um clique dispara o build, que lê o banco e gera as páginas estáticas.
4. Site atualizado Se tudo deu certo, a nova versão entra no ar; se algo falhou, a anterior continua.
03 • Destaques

O que vai além de um site de vitrine

Além do fluxo de publicação, o projeto resolve rotinas do dia a dia da imobiliária e cuida do que o visitante não vê, mas sente.

01 / SEASONAL RENTALS

Gestão de temporada

Agenda geral por período com todas as casas, exportação para planilha no mesmo modelo que o cliente já usava e pré-reservas com prazo de validade.

02 / PHOTOS

Fotos e características

Fotos enviadas direto do painel para o Supabase Storage, com limite de tamanho, e otimizadas para ficarem mais leves no site. As características do imóvel são escolhidas num seletor visual de ícones.

03 / CRM

Base de contatos (CRM)

Uma base de CRM para os contatos (leads) está em construção, para que os interessados fiquem organizados num só lugar, dentro do mesmo painel.

04 / SHARING & SEO

Compartilhamento e SEO

Prévia de link bonita no WhatsApp com Open Graph e SEO técnico com sitemap e canonical, para o imóvel ser bem apresentado onde é compartilhado e encontrado.

05 / INFRASTRUCTURE

Infraestrutura enxuta

Quando o plano gratuito da Netlify acabou, a hospedagem foi migrada para o Cloudflare. Uma tarefa agendada no GitHub Actions mantém ativo o banco do plano gratuito.

06 / QUALITY

Qualidade e testes

Mais de 330 testes automatizados (node:test + Playwright) e desenvolvimento em PRs pequenos e revisados, para cada mudança chegar ao ar sem surpresas.

04 • O Que Mudou

O dono publica sozinho, e o site não quebra

Hoje o dono cadastra, edita e publica os imóveis de venda sem depender de ninguém. Os 11 imóveis de venda iniciais já foram todos importados para o painel, e uma alteração chega ao site com um clique em “Publicar no site”.

A temporada ganhou uma visão de todas as casas por período, e a planilha continua no formato de sempre, agora gerada pelo sistema. Com perfis separados, o assistente ajuda na operação sem poder exportar ou apagar dados.

O projeto segue em evolução desde 2024, com a base de CRM como próximo passo, sempre em entregas pequenas, revisadas e testadas.
